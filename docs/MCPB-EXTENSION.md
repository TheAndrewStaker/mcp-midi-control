# Claude Desktop Extension (`.mcpb`)

The `.mcpb` is the **one-click install** — and the front door this project most
wants for blind users. It removes every screen-reader-hostile step the source
build leans on:

- **Install is one action inside Claude Desktop** (Settings → Extensions →
  Install, or open the `.mcpb`). Claude Desktop writes its own config — no
  Terminal, no editing `claude_desktop_config.json`.
- **No Node, no Xcode, no compile.** Claude Desktop ships its own Node runtime;
  the extension bundles the prebuilt native MIDI binary.
- **No Gatekeeper "unidentified developer" wall** and **no $99 Apple Developer
  fee** — Claude Desktop unpacks the `.mcpb` internally, so the user never
  launches a standalone unsigned binary (the thing macOS blocks).

See [`docs/design/accessibility-blind-support.md`](design/accessibility-blind-support.md)
for why this is the mission-level deliverable, and
[`docs/INSTALL-MAC.md`](INSTALL-MAC.md) for the source-build fallback.

## Status

**Authored, not yet validated on a Mac.** The native prerequisite (the
`@julusian/midi` prebuilt swap) has shipped, which unblocked this. The builder
and manifest below are written and pass on the build host; what remains is
running them on a Mac and installing the result in Claude Desktop end to end.
This follows the project's evidence-over-keypress bar: the path is built and
load-tested, and is "untested on a Mac," not "unbuilt."

What IS validated: the cross-platform native stack runs in CI
(`.github/workflows/native-matrix.yml`) on macOS arm64 + x64 and Linux — each
job loads the `@julusian/midi` and `serialport` prebuilds and round-trips a
SysEx through a virtual port (`npm run verify-loopback-midi`), so the receive
path the extension depends on is proven per-platform without hardware.

## Build

```
npm run build:mcpb
```

Produces `build/dist/mcp-midi-control-v<version>-<platform>-<arch>.mcpb`. The
builder (`scripts/build-mcpb.ts`) mirrors the release-ZIP staging
(`build-installer.ts`): a lean root `package.json` → `npm install --omit=dev`
the leaf deps → copy each workspace package as a real directory under
`node_modules/@mcp-midi-control/`. It then generates `manifest.json` from
`package.json` (version + metadata never drift), load-tests both native
bindings, smoke-boots the server, and packs the `.mcpb` (a zip with
`manifest.json` at the root).

**Per-platform artifact.** `npm install` fetches the prebuilt bindings for the
**build host's** platform/arch, so each `.mcpb` is correct for the host and is
named accordingly (`…-darwin-arm64.mcpb`). Build the blind-user target on a
`macos-14` (Apple Silicon) runner. The maintainer develops on Windows, so the
darwin artifacts come from CI or a contributor's Mac.

## Validate and install (on a Mac)

```
npx @anthropic-ai/mcpb validate build/mcpb-staging/manifest.json
```

Then open the `.mcpb` in Claude Desktop (Settings → Extensions) and confirm a
read + a write against connected gear. If any step fights VoiceOver, that
feedback shapes the install — file it.

## Manifest shape (generated)

Generated by `build-mcpb.ts` to the `anthropics/mcpb` schema:

- `server.type: "node"`, entry at
  `node_modules/@mcp-midi-control/server-all/dist/server/index.js`, launched as
  `node ${__dirname}/<entry>`.
- `tools_generated: true` — the server registers its full surface at runtime;
  Claude Desktop discovers it on connect (so the manifest never drifts from the
  tool list).
- `user_config.fm3_serial_path` — an **optional** string, bound to
  `MCP_FM3_SERIAL_PATH`. Only the FM3 needs it (USB-serial, not MIDI); blank
  means auto-detect.
- `compatibility.platforms`: darwin / win32 / linux; `runtimes.node: ">=20"`.

## Open items

- **Universal (multi-platform) `.mcpb`.** Today's artifact carries one
  platform's prebuilds. A single cross-platform extension needs every
  platform's prebuilds bundled; `@julusian/midi` ships N-API prebuilds, but
  `serialport`'s binding is fetched per-platform. Ship per-platform artifacts
  first; revisit a universal bundle later.
- **FM3 over the extension.** The class-compliant USB-MIDI devices
  (III / FM9 / VP4 / AM4 / Hydrasynth) are the clean first target. The FM3's
  serial transport works through the same model, but its exclusive-port rule is
  extra friction; add it after the MIDI-class path is proven.
- **End-to-end Mac validation + an accessible, screen-reader-tested install
  walkthrough** for the `.mcpb` flow.
