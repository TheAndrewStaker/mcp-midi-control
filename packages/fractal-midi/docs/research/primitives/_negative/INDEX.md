# Encoding Primitives: Negative Findings Index

> Check this table BEFORE re-attempting a method that "feels useful but
> might already be ruled out." Every entry is a dead end that cost at
> least one session; the grep terms are what a future agent would search
> right before burning the next one.

Entries carry `status: non-matching` and live in this directory. Each has
a Symptoms / grep terms (or Search terms) section for findability; the
`primitives-verify` gate enforces both the section and this index staying in
sync with the directory. Each also carries required frontmatter
`retest_when:`, either a list of re-test triggers (primitive slugs and/or
free-text conditions) or the literal `never (<reason>)`. When a listed
trigger primitive lands as matched, `primitives-verify` nags (warn; fail
under `--strict`) until the negative is re-adjudicated or its
`retest_when` updated: the machine remembers the trigger; the human
judges the verdict.
